# Data contracts and model grain

## Sources

All files in `data/sample` are generated by `commerce_pipeline.generate_sample_data` with
seed 42. No real people or employer data are included. Date coverage is fixed; data freshness
relative to today's date is not an operational health claim.

| Raw table | One row represents | Key |
|---|---|---|
| customers | A synthetic customer | customer_id |
| products | A product | product_id |
| sessions | A customer acquisition session | session_id |
| orders | An order, including cancelled/refunded orders | order_id |
| order_items | A line in an order | order_item_id |

`orders.customer_id` must match the referenced session's customer. An order must not precede
its session; a session must not precede the customer's signup date. Every order needs items.
The demo and a source uniqueness test currently enforce at most one order per session; the
channel model pre-aggregation can support multiple orders once that source contract changes.

## Transformations

| Model | Grain | Key behavior |
|---|---|---|
| stg_customers | customer | Pass through identity, region and signup date |
| stg_products | product | Pass through category and synthetic cost |
| stg_sessions | session | Derive UTC session date |
| stg_orders | order | Derive UTC order date |
| stg_order_items | order item | Calculate quantity × unit price |
| int_orders_enriched | order | Sum items; recognize revenue for paid status only |
| mart_daily_sales | UTC order date | Counts by status, revenue, paid-order AOV |
| mart_channel_performance | acquisition channel | Sessions, converted sessions, revenue, conversion |
| mart_category_performance | product category | Paid units, revenue, estimated product margin |
| mart_customer_repeat | entire dataset (one row) | Paying/repeat customers and repeat buyer rate |

These are not yet fact/dimension models. The intermediate inner join assumes at least one
item per order, enforced by `assert_orders_have_items`. A missing-item order must fail checks
rather than be treated as a legitimate zero-value order.

## Consumer contracts

KPI cards and breakdowns always cover the complete dataset. Trend window selection changes
only the revenue chart. Missing calendar days in that chart are filled with zero; the rolling
average begins after seven daily observations. Mini SVG charts use actual weekly aggregates,
including partial boundary weeks; they do not show invented performance deltas.

Channel table search filters the rows and CSV export. Conversion is displayed as a percentage
in the table; the CSV `Conversion` field remains a fraction between 0 and 1. Repeat buyer rate
covers purchases in this dataset, not customer lifetime or retention cohorts. Product margin
excludes shipping, tax, overhead and marketing spend.

The dashboard revenue indicator checks exact totals from four marts against raw paid items
at read time, with a 60-second query cache. It is not a scheduler, anomaly detector or persistent
pipeline monitor. Detailed assertions run through dbt and the CSV verifier.
